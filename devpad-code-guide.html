What happens when you type a letter (the GUI path)

  1. CodeView::keyPressEvent receives the key and calls typeChar(c).
  2. If text is selected and "wrap selection" is on and the key is a bracket/quote, toggleSurround wraps it; otherwise the selection is replaced.
  3. If the next character already equals the typed closer () ] } quote) and auto-pairs are on, the cursor just steps over it.
  4. If it is an opener and shouldAutoPair says yes, both characters are inserted and the cursor goes between them.
  5. Otherwise Editor::typeText inserts it. It merges with the previous key press into one undo step when they touch and are the same character class.
  6. Document::insertText edits the one line's DynArray<char> (the only line touched).
  7. CodeView::edited marks syntax state and brackets as stale, starts an 80 ms timer, updates the scrollbars and repaints only the visible lines.
  8. edited also calls shiftFolds: if the edit added or removed lines, folded blocks below it move with the text (FoldSet::linesChanged), and the word-wrap row table is marked stale (invalidateRows).
  9. When the timer fires with no further typing, recomputeBrackets runs checkBrackets once (O(N)); from the same report it rebuilds the fold ranges (foldRangesFromBrackets) and the symbol list (outlineSymbols), corrects the folds (keepOnly) and emits outlineChanged, so the squiggles, the bracket highlight, the Outline panel and the breadcrumbs all update together.
  10. For a C / C++ file, MainWindow restarts a 350 ms timer; when it fires, SyntaxChecker compiles a temporary copy with g++ -fsyntax-only in the background and the Problems tab, the status-bar counter and the red / yellow squiggles update.
  11. If the word before the cursor is a snippet trigger, the suggestion list shows it first; Tab (or accepting it) calls applySnippet, which replaces it in one undo step.

Algorithms, step by step

For each prominent feature: the idea, the data it uses, the explicit steps exactly as the code does them, the cost, how it can fail, and where it lives. Every demo below is a faithful JavaScript port of the C++ logic, so what you see is what the C++ does.

1. DynArray: the growable array

Used for: characters of a line, result lists, trie edges, stack storage. File: engine/DynArray.h

  1. Keep three fields: data_ (pointer), size_ (items used), cap_ (slots allocated).
  2. push_back(x): if size_ == cap_, call reserve(cap_ ? cap_*2 : 8).
  3. reserve(n): allocate new T[n], copy the size_ old items, delete[] the old block, store the new pointer and capacity.
  4. Store x at data_[size_] and increment size_.
  5. insert(i,x): check i <= size_, grow if full, shift items i..size_-1 one place right, write x.
  6. erase(first,last): check first <= last <= size_, shift the tail left over the gap, reduce size_.

Why doubling? A copy costs O(n) but happens only when the size hits 8, 16, 32, ... so the copies add up to less than 2n for n pushes: O(1) amortised per push.

Demo: watch the capacity double

Fails when: memory runs out (std::bad_alloc) or an index is bad (at, insert, erase throw out_of_range). operator[] is unchecked for speed, so callers must stay inside size().

2. Document: doubly linked list of lines

Files: engine/Document.h/.cpp. Representation: Node{ DynArray<char> text; Node* prev; Node* next; } plus head_, tail_, lineCount_, charCount_ and a cache (cache_, cacheIdx_).

Why a linked list of lines? Pressing Enter or deleting several lines only rewires pointers. A single big array of lines would shift every later line. Editing inside a line touches one short array.

2a. nodeAt(line): find a line

  1. If line >= lineCount_ throw out_of_range("line number out of range").
  2. Compute three distances: from head d = line, from tail d = last - line, from the cache d = |line - cacheIdx_|.
  3. Start from whichever start has the smallest distance (cache wins ties first).
  4. Walk next pointers forward or prev pointers backward until the index equals line.
  5. Store the node as the new cache. Return it.

Typing and scrolling touch the same or neighbouring lines, so the cache makes them O(1). A jump to a random line costs at most half the document, never more.

2b. insertText(at, text)

  1. checkPos(at): line exists and col <= length, otherwise throw (nothing changed yet).
  2. Copy the part of the current line after at.col into a temporary tail and cut the line at at.col.
  3. For each character of text: skip '\r'; on '\n' create a new Node and link it after the current node (fix prev/next, update tail_ if it was last), make it current; otherwise push_back the character on the current line.
  4. Remember the end position (current line, current length).
  5. Append tail to the current (last inserted) line.
  6. Update the cache to the last touched line, mark modified, return the end position.

2c. deleteRange(a, b)

  1. Swap if b < a; validate both positions; if equal return empty string.
  2. Save the text getRange(a,b) (it will go on the undo stack).
  3. Same line: erase columns a.col..b.col in that line's array.
  4. Several lines: cut line A at a.col, append the part of line B after b.col to it, then unlink and delete every node after A up to and including B, fix prev/next/tail_, reduce the counters.
  5. Cache = line A. Return the removed text.

3. Undo / Redo with two stacks, groups and typing runs

Files: Command.h, UndoManager.h, Stack.h, Editor.cpp.

Key idea: every edit is one of two primitives, so the inverse is the other primitive. Command{type, start, end, text}:

CommandApply (redo)Reverse (undo)
Insert start..end with textinsertText(start, text)deleteRange(start, end)
Delete start..end that held textdeleteRange(start, end)insertText(start, text)

3a. Recording an edit

  1. The Editor performs the edit on the Document first. If it throws, nothing is recorded.
  2. Build a Command with the positions and text.
  3. If inside beginGroup/endGroup (depth > 0): append it to pending_. Otherwise wrap it in a Group with a label ("insert", "delete word"...).
  4. UndoManager::record(group): push on the undo stack, clear the redo stack (a new edit makes the old future meaningless), trim the undo stack to 100 groups (oldest dropped).

3b. Undo

  1. If inside a group or the undo stack is empty, return false.
  2. End any typing run. Pop the top Group.
  3. Reverse its commands from newest to oldest (so the text passes through its earlier states).
  4. Push the group on the redo stack. Report the label and the cursor position (end of restored text).

3c. Redo

  1. Pop the top of the redo stack, apply its commands from oldest to newest, push it back on the undo stack.

3d. Typing runs (why Ctrl+Z removes a word, not a letter)

  1. Classify each typed character: 0 letter/digit/_ (and UTF-8 bytes), 1 blank (space, tab), 2 other.
  2. typeText(at, s) merges into the previous undo step only if ALL hold: not inside a group; the text is one class (no newline); the last action was typing; the undo count is unchanged since then; at == runPos_ (the cursor did not move); same class as the last character.
  3. When merging: append the text to the existing Command, move its end, clear redo. Otherwise record a new "typing" group.
  4. Any other edit, undo/redo, open, or a cursor move (breakTyping()) ends the run.
  5. eraseCoalescing does the same for Backspace (new deleted text lies just before the old: prepend) and Delete (just after: append).

So typing hello world makes 3 undo steps: hello, ␠, world. Memory stays O(characters typed).

4. Search: Knuth-Morris-Pratt

Files: engine/Search.cpp (buildFailureTable, KmpMatcher, scan, findAll, findNext).

Problem with brute force: after a mismatch it moves the text pointer back and re-compares: O(n·m) worst case. KMP never moves the text pointer back.

4a. Failure table f[i] = length of the longest proper prefix of p[0..i] that is also its suffix

  1. f[0] = 0; k = 0.
  2. For i = 1..m-1: while k > 0 and p[i] != p[k]: k = f[k-1] (fall back inside the pattern).
  3. If p[i] == p[k] then k++.
  4. f[i] = k.

4b. Feeding characters (KmpMatcher::feed(c))

  1. If case-insensitive, fold A-Z to lower case (pattern and text).
  2. While state > 0 and pat[state] != c: state = f[state-1].
  3. If pat[state] == c: state++.
  4. If state == m: a match ends here. Set state = f[m-1] (not 0!) so overlapping matches like "aa" in "aaa" are found. Return true.

4c. Searching a Document (scan)

  1. Quick exit: pattern longer than charCount + lineCount - 1 can never match.
  2. For each line from the start position: feed its characters; on a match compute start = walkBack(end, m) (only multi-line patterns walk to previous lines).
  3. Between lines feed '\n' so a pattern containing a line break can match across lines.
  4. Whole word: only check a side if the pattern itself starts/ends with a word character; reject if the neighbouring character is a letter, digit or _.
  5. Pass each accepted match to the callback; findNext stops at the first, wraps around once if nothing was found after the start; findAll(..., allowOverlap=false) skips a match that starts before the previous one ended.

5. Replace All: right-to-left with rollback

File: Editor::replaceAll in engine/Editor.cpp.

  1. hits = findAll(doc, pattern, opt, allowOverlap=false). Empty pattern throws here, before anything changes. No hits: return {found 0} and record nothing.
  2. beginGroup("replace all") and remember mark = number of commands already pending (from an outer group).
  3. Walk the hits from the last to the first. A replacement only moves text after it, so positions of the hits still to do stay valid. No position bookkeeping needed.
  4. If the matched text already equals the replacement, skip (so changed can be smaller than found).
  5. replaceRange(start, end, replacement) = delete + insert in the current group.
  6. If anything throws: reverse the commands of this call newest-first (removing each only after it was reversed), end the group, rethrow. The text is back as before and no history entry exists.
  7. Normal finish: endGroup() records one undo step for all replacements.

Fails when: empty search text (before any change); any exception during replacement (rolled back; only the test hook injects one). Atomicity is proven by testReplaceRollback.

Cost: O(n+m) to find, then O(k·(len + line tail)) for k replacements.

6. Bracket checker with a stack

Files: engine/Brackets.cpp, Stack.h.

  1. Create an empty stack of Open{char, Pos} and a lexer state: Code, LineComment, BlockComment, Raw string.
  2. Scan each line left to right. In Code state: // starts a line comment (continues if the line ends with \), /* a block comment, " a string (skip to the closing quote, honouring \ escapes; an unclosed string on one line is an issue), R"delim( a raw string, ' a char literal unless it is a digit separator like 1'000.
  3. Brackets inside comments or strings are ignored.
  4. Opener ( [ {: push (character, position); update max depth.
  5. Closer ) ] } with its wanted opener w:
    1. stack empty → issue UnmatchedClose, nothing popped;
    2. top is w → pop, record a matched pair with its depth;
    3. otherwise search deeper in the stack (peek(depth)) for w: if found, every opener above it is reported Unclosed and popped, then the pair is matched;
    4. not found anywhere → Mismatch: report, pop the top (treat it as a wrong-kind typo).
  6. At end of text: unterminated /* or raw string → issue; every opener left on the stack → Unclosed (listed in text order).

Demo: bracket checker

Fails when: never throws on normal text; problems are returned as issues (capped at 200, truncated flag). matchNearCursor throws out_of_range if the cursor is not a valid position. Limitation: only C-style lexing (no < > templates, no Python triple quotes, so bracket checking in other languages can show false issues).

Cost: O(N) time, O(max nesting + pairs) memory. The GUI re-runs it 80 ms after typing stops, and skips it above 4,000,000 characters.

7. Autocomplete: Trie + threshold ranking

Files: engine/Trie.cpp, engine/Assist.cpp.

7a. Trie structure

  1. All nodes live in one DynArray<Node>; children are referred to by index (safe when the array grows). Node: edges (sorted by character), isWord, weight.
  2. insert(word, w): reject if empty, longer than 64, or has space/control characters. Walk from the root: childOf(node, ch) by binary search over the sorted edges; if missing, addChild inserts the edge in sorted position. Mark the last node as a word and add w to its weight (saturating at 232-1).
  3. complete(prefix, k): walk to the prefix node (none → empty list). Then an iterative DFS (explicit stack of frames, no recursion) visits words alphabetically. Each word found is inserted into a small sorted array (weight descending, then alphabetical) of at most k entries; the worst is dropped.
  4. remove(word): just unmark isWord and zero the weight; compact() rebuilds the tree from the remaining words.

7b. Combining two tries (Autocomplete::suggest)

Score of a word = weight in the C++ dictionary + weight in the words of the current document.

  1. Let m = k + 1 (the prefix itself may take a slot).
  2. Ask each trie for its top m words: lists A and B.
  3. Bound: a word in neither list scores at most (m-th weight of A) + (m-th weight of B) (a list that is not full contributes 0).
  4. Union the candidates (skip the prefix itself), compute each score, pick the best k by repeated selection (ties alphabetical).
  5. If both lists were not full (exhausted) or the k-th best score is strictly greater than the bound, the answer is final. Otherwise m *= 2 and repeat.

8. Quick Open: fuzzy subsequence scoring (dynamic programming)

File: engine/Workspace.cpp (fuzzyScore, rankFiles, listWorkspaceFiles). Typing mwcp finds gui/MainWindow.cpp.

  1. Normalise: \ becomes /; remove blanks from the query. Empty query → score 0. Query longer than the candidate → -1 (no match).
  2. Precompute bonus[j] for every candidate position: start of a path segment +16; after _ - . space +10; camelCase hump +8; plus +4 if inside the file name (after the last slash).
  3. DP over query characters i and candidate positions j with two arrays: M[j] = best score with query char i matched exactly at j; D[j] = best with it matched at some k ≤ j, each skipped character after it costing 1.
  4. If cand[j] equals q[i] (case-insensitive): base = 1 + bonus[j] + (exact case ? 1 : 0). For the first query char the predecessor is 0; otherwise the predecessor is prevM[j-1] + 12 (directly consecutive) or prevD[j-1] (gap), whichever is larger. M[j] = base + predecessor.
  5. D[j] = max(M[j], D[j-1] - 1).
  6. Only two rows are kept (rolling arrays). Result = D[n-1] after the last query char; never negative; impossible = -1.
  7. rankFiles: score every file, keep the best maxResults in a small sorted array by insertion; better = higher score, then shorter path, then alphabetical. Blank query returns the first files in order.

9. Line operations, smart Enter and auto-pair

File: engine/EditOps.cpp. Each operation opens an EditGroup, so one Ctrl+Z reverses all of it.

9a. Smart Enter (insertNewLineSmart)

  1. Read the line; indent = leading blanks of the text before the cursor.
  2. last = last non-blank character before the cursor; first = first non-blank after it.
  3. If last is an opener and first is its closer ({|}): insert "\n" + indent + unit + "\n" + indent; cursor on the middle line (indent + one unit).
  4. Else insert "\n" + indent, plus one extra indent unit if last is an opener.

9b. Toggle comment (toggleLineComment)

  1. Pass 1 over the selected lines: ignore blank lines; find the smallest indentation; check whether all non-blank lines already start with the marker.
  2. If all are commented: delete the marker (and one following space) on each line. Otherwise: insert marker + " " at the smallest indentation on every non-blank line (comments line up).
  3. Return the column shifts so the GUI can move the cursor and selection.

9c. Move lines (moveLines)

  1. Take the block from..to and its neighbour line (above for up, below for down); if there is none return false.
  2. Replace the two-part range by the swapped text in one replaceRange inside a group.

9d. Auto-pair

  1. Typing a closer that equals the next character → cursor steps over it (nothing inserted).
  2. Typing an opener where shouldAutoPair is true → insert both and put the cursor between.
  3. With a selection and "wrap selection" on → toggleSurround: wrap, or if already wrapped by the same pair, unwrap.

10. File I/O and the file manager

File: engine/FileIO.cpp. Never throws: returns IOResult{ok, message}.

  1. Open: empty path → message; forbidden characters → message; open the file in binary mode; read all bytes; loadFromString (drops \r; a trailing newline does not create an extra empty line); remember crlf = content contains "\r\n"; set path; mark saved.
  2. Save: same name checks; open for writing with truncate; toString(); if crlf convert each \n to \r\n; write; flush; check the stream state (disk full); mark saved.
  3. Names: reject < > " | ? *, and : unless it is a drive letter in position 2, so the error is the same on every operating system.
  4. Rename / move / copy / create: use std::filesystem with error codes; refuse existing targets; refuse moving a folder into itself (isSameOrInside); copies get a free name ("name copy", numbered up to 9999).

Fails when: file missing, no permission, path is a folder, disk full, invalid name, target exists. All reported as readable messages (see the error catalogue). Limitation: the whole file is read into memory.

11. The GUI: painting, keys, highlighting

  1. Rows, not lines: the vertical scroll bar counts screen rows. Without folds or wrap a row is a line. A folded block adds 0 rows, a wrapped line adds as many as it needs. rowOf(line) and lineAtRow(row) translate both ways (see folding and word wrap).
  2. Painting: CodeView::paintEvent finds the line on the first visible row, then walks down the visible lines (jumping over folded blocks with FoldSet::nextVisible) until the window is full. For each line it gets the row starts (wrapStarts: just {0} without wrap) and draws, row by row, the current-line band, search highlights, selection, indent guides, text tokens, the "⋯" pill of a folded header, squiggles, the bracket highlight and the caret. A helper forRows(a, b, fn) cuts every column range into one piece per row it covers. Finally the gutter: line numbers, fold arrows and error dots. Cost depends on the window, not on the file size.
  3. Syntax colours: tokenize splits a line into spans of ten classes: plain text, keyword, type (also capitalised names such as CodeView), string, number, comment, preprocessor, function call (a name followed by (), operator (runs of +-*/%=<>!&|^~?:) and constant (true, nullptr, ALL_CAPS). Each theme gives every class its own colour. The only state carried between lines is "inside a block comment"; ensureBlockState caches it up to blockValid_, and an edit lowers blockValid_ so only lines after the edit are recomputed.
  4. Bracket feedback: every edit sets dirtyBrackets_ and (re)starts an 80 ms timer; recomputeBrackets calls checkBrackets; matchNearCursor picks the pair to highlight.
  5. Autocomplete popup: showCompletions takes the word before the cursor (prefixBefore), asks Autocomplete::suggest, shows a list; accepting calls applyCompletion inside one group.
  6. Find bar: highlights all matches with findAll, Enter/Shift+Enter use findNext (wrapping), Replace uses replaceRange, Replace All calls Editor::replaceAll (one undo step).
  7. Squiggles: diagnostics from the bracket checker and the compiler are drawn as a red (error) or yellow (warning) wavy underline, as long as squiggleLength says, with a dot in the gutter and the message as a tooltip.
  8. Session: on close the open files, current tab, folder, geometry and panel states go to QSettings; on start they are restored (if the setting is on).

12. Settings: live-applied preferences

  1. AppSettings is a singleton holding a Values struct; it loads from QSettings at start (load).
  2. A control in the Settings window calls apply(values).
  3. sanitized() clamps each field (font size, tab width, scrollback...) and checks the accent key, so a bad value can never be stored.
  4. The values are saved and changed() is emitted.
  5. Every listener reacts: each CodeView::applySettings (font, tab width, line numbers, guides, caret...), Theme::setScheme / Theme::setAccent rebuild the style sheet with the new theme and accent colour, the terminal updates its font and shell, the status bar is shown or hidden.
  6. Themes: 14 themes in 7 light / dark pairs (Midnight / Daylight, Nord / Solarized Light, Dracula / Alucard, Monokai / Paper, Gruvbox Dark / Light, Tokyo Night / One Light, Jellyfish / Jellyfish Light), each with ten syntax colours; Ctrl+Shift+L switches to the partner. See themes.
  7. Word wrap and breadcrumbs are two more settings (wordWrap, off by default; breadcrumbs, on). View > Word Wrap (Alt+Z) and View > Breadcrumbs flip them through AppSettings::apply, and the menu ticks follow the Settings window because they listen to changed() too.
  8. Auto save (off by default): after the chosen idle delay (1 to 300 s) MainWindow saves every modified tab that already has a file name.

13. F5 Run and the terminal

  1. runCurrent: no tab → status message. Otherwise save the file first (the program must be what is on screen); if saving fails, stop.
  2. Runner::planFor(path, shell, tempDir) returns the command lines for the extension (see the Runner entry in the atlas): e.g. g++ -std=c++17 file.cpp -O0 -g -o tmp/file.exe then the exe. Quoting is generated for the active shell (POSIX / cmd / PowerShell).
  3. The terminal panel is shown. An empty plan (unsupported extension) shows "DevPad cannot run .ext files (F5 runs: …)".
  4. Working directory = the file's folder. runSequence(steps) queues the commands.
  5. For each command a QProcess starts the shell with it; output (stdout+stderr merged) streams into the panel with ANSI colours.
  6. When a command finishes: non-zero exit or crash → print [exit code N] or [stopped] and clear the queue, so a failed compile never runs an old exe; otherwise start the next command.
  7. Shift+F5, or the Stop button of the Run / Stop group at the right end of the tab strip, stops the process. A 200 ms timer asks the terminal whether it is busy(): while it is, Run is dimmed and Stop red; otherwise Run is green and Stop dimmed (refreshRunButtons). The group is placed by placeRunGroup in the middle of the tab bar's height, because Qt lines a tab widget's corner up with the bottom of the tab area.
  8. When the compiler prints file.cpp:12:5: error: …, that text in the terminal is a link: hover underlines it, a click opens the file at line 12, column 5 (see terminal links).

Fails when: the compiler/interpreter is not installed or not on PATH (the shell prints its own message and a non-zero exit code); the shell program cannot start (message pointing to Settings → Terminal).

14. Hash table and code snippets

Files: engine/HashTable.h, engine/Snippets.h/.cpp, applySnippet in engine/Assist.cpp; GUI: SnippetStore, SnippetDialog.

Why a hash table? Expanding a snippet asks one question: "is the word before the cursor a trigger?". No ordering and no prefixes are needed, so a hash table answers in O(1) expected time (a trie would cost O(w log s), a sorted array O(log h) string comparisons).

14a. The table: separate chaining

  1. Storage: DynArray<Node*> buckets_ (16 at the start), each a singly linked list of Node{key, value, next}, plus size_.
  2. Hash (FNV-1a, 64 bit): h = 1469598103934665603; for every byte: h ^= byte; h *= 1099511628211. Bucket = h % bucketCount.
  3. get / contains: hash the key, walk that one chain comparing keys.
  4. put: if the key exists, overwrite the value. Otherwise, if (size + 1) > 0.75 × buckets, grow first; then push a new node at the head of its chain (O(1)).
  5. grow: allocate twice as many buckets and relink every node into its new bucket. No node is allocated, so a rehash cannot fail half way.
  6. erase: walk the chain keeping the previous node, unlink and delete the match.

14b. Expanding a snippet (applySnippet)

  1. Take the word that ends at the cursor (letters, digits, _). No word, or the cursor inside a word → not expanded, with a reason (not an error).
  2. table.find(word): one hash lookup. Not found → "for" is not a snippet.
  3. expandBody(body, indent): read the body once; $0 becomes the cursor position, $$ becomes $, and the indentation of the current line is added after every line break.
  4. replaceRange(start of word, cursor, text) inside one group labelled "snippet": one undo step. The cursor goes to $0, or to the end of the text.

Demo: buckets and chains

Real FNV-1a (64 bit) and the real growth rule. Start with 16 buckets; watch the table double when the load factor would pass 0.75.

Fails when: an invalid trigger (1-32 letters, digits or _, not starting with a digit) or body (empty, over 4,000 characters, a \r or NUL, two $0) → invalid_argument before anything changes; more than 500 snippets → length_error; snippet files report problems as IOResult messages.

Cost: put / get / erase O(1) expected (O(h) worst case if every key collided); rehash O(h + buckets), O(1) amortised per put; expansion O(word + body + line).

17. Code folding: which lines can fold, and the line ↔ row map

Files: engine/Folding.h/.cpp (foldRangesFromBrackets, foldRangesByIndent, FoldSet); GUI: CodeView (arrows, toggleFold, foldAtCursor, foldAll).

A fold range is {start, last}: the header line start stays visible, lines start+1 … last disappear.

17a. Finding the ranges

  1. C-like code: take every bracket pair from the bracket report. A pair that opens on line o and closes on line c with c ≥ o + 2 gives the range {o, c − 1}: the line with the closing bracket stays visible, so } else { is never hidden.
  2. One range per line, sorted, without sorting: an array lastOf[line] keeps the largest last seen for each opening line (a { beats a ( that opens on the same line and closes earlier). Reading the array from top to bottom yields the ranges already in order: a counting sort by line, O(lines + pairs).
  3. Python / scripts: a Stack of open blocks {line, indent}. Each non-blank line first closes (pops) every open block whose indent is ≥ its own; a closed block becomes a range up to the last non-blank line inside it. Blank lines belong to whatever is open. One pass, O(N).

17b. What is folded: FoldSet

  1. The folds the user closed are kept sorted by start line (folds_). Folds inside folds are allowed.
  2. rebuild() merges their hidden parts [start+1, last] into disjoint intervals hs_[k] … he_[k], and stores before_[k] = hidden lines in all earlier intervals (prefix sums).
  3. rowOf(line): binary-search the number of intervals that start at or before the line. If the line is inside one, it is hidden: use the header above it. Row = line − hidden lines before it. O(log k).
  4. lineAt(row): interval k starts after hs_[k] − before_[k] visible rows; binary-search the last interval that starts at or before the row, then line = row + all hidden lines up to and including it. O(log k).
  5. After an edit: linesChanged(fromLine, delta) moves folds below the edit, grows / shrinks a fold around it, drops a fold that became empty. When the next bracket report arrives, keepOnly(validRanges) keeps only folds whose header can still fold, with the new extent.
  6. The cursor is never hidden: CodeView::ensureCursorVisible calls reveal(line), which opens every fold around the cursor, so search, Go to Line, a click in the Outline or Undo all open the block they go into. Folding a block that contains the cursor moves the cursor to the end of the header first (moveCursorOutOfFolds).

Demo: FoldSet (a faithful port)

Folds as start-last (0-based lines), separated by commas. Nested folds are fine.

Fails when: a fold that is already folded or has nothing to hide (fold returns false). Brace-based ranges depend on the bracket report: while the brackets are unbalanced (half-typed code) some ranges disappear and folds on them are dropped. Cost: ranges O(lines + pairs); fold / unfold / reveal O(k); rowOf / lineAt / isHidden O(log k).

18. Outline: finding classes and functions without a compiler

Files: engine/Outline.h/.cpp (outlineSymbols, outlineScriptSymbols, symbolAtLine); GUI: OutlinePanel in gui/SidePanels.cpp, breadcrumbs.

  1. Order the braces: the bracket report lists pairs by their closing bracket. The { pairs are bucketed by opening line (counting sort with prefix sums of bucket sizes) and sorted by column inside a line, giving them in reading order. O(lines + pairs).
  2. Read the header of each {: the text in front of it on its line (headerOf). Earlier lines are joined while a ) has no ( yet (parameters over several lines), when the brace stands alone (Allman style), or for a constructor's : a(1), b(2) list. // comments are cut off.
  3. Class-like? (classLike) skip a leading template<…>; find namespace / class / struct / union / enum outside parentheses; reject the header if it has = or ; (an initializer). The name is the last word before : (base classes / underlying type); enum class X skips the word class; no name → "(anonymous)".
  4. Function-like? (functionLike) find the first (, take the name in front of it (letters, digits, _, ::, ~; operator== and operator() are handled). Reject keywords (if for while switch catch return sizeof …), names after . or ->, anything that is not a return type in front (only identifiers, :: < > * & [ ]). The key test: the parameter list must close before the {. In connect(a, b, [this]() { the call's ( is still open, so the brace belongs to a lambda: not a function. What follows ) may only be const override final noexcept -> : volatile & throw try requires mutable.
  5. Constructors written inside a class have no return type; they are accepted only if the enclosing symbol is a class / struct with the same name (or ~name).
  6. Nesting: a Stack holds the symbols still open. Before each new brace, symbols whose closing bracket comes earlier are popped; the stack size is the new symbol's depth. Accepted symbols are pushed.
  7. Python / scripts: lines starting with def, async def, function or class; a stack of {indent, index} gives depth and end line, as in folding.
  8. symbolAtLine(line): the deepest symbol whose range contains the line: the Outline highlights it and the breadcrumbs list the chain.

Fails when: never throws. It is a reading of the text, not a parser: macros that look like calls, a K&R-style header split oddly, or code with unbalanced brackets can be missed or misread. Cost: O(N + pairs).

19. Undo History: the two stacks as one timeline

Files: engine/UndoManager.h (undoStep, redoStep), engine/Editor.cpp (jumpToHistory, describeStep), HistoryPanel in gui/SidePanels.cpp, CodeView::jumpToHistory.

  1. Read without popping: undoStep(i) = undo_.peek(size − 1 − i) gives the i-th oldest step still undoable; redoStep(j) = redo_.peek(j) gives the step Redo would apply next. Stack::peek is O(1).
  2. The timeline: row 0 is the state before the oldest kept step ("Opened / start", or "Oldest kept state" once the 100-step limit has dropped older ones); row k is the state after undo step k; then the redo steps, dimmed. The current state is row undoCount, shown bold and selected.
  3. Labels: describeStep turns a group into insert "hello" line 3: the label, the text of a one- or two-command step (line breaks shown as ↵, cut at 28 characters), or "(N changes)" for a big group such as replace all.
  4. Jumping: clicking row r calls jumpToHistory(r): undo() while more than r steps are undoable, redo() while fewer. Each step is reversed exactly as Ctrl+Z / Ctrl+Y would, so the result is identical to pressing them by hand.
  5. Refreshing cheaply: the panel rebuilds only when the revision, the undo count or the redo count changed, not on every cursor move.

Cost: building the list O(steps) ≤ 100 + redo; a jump O(steps moved × their size). A new edit after jumping back clears the redo part, like any edit.

20. Word wrap: rows as prefix sums

Files: gui/CodeView.cpp (wrapStarts, ensureRows, rowOf, lineAtRow, cellAt, posAtRow). Keys: Alt+Z.

  1. Where one line breaks: wrapStarts(line) returns the display column where each of its rows starts. Width in columns = (viewport width − gutter) / character width. Break after the last space that still fits (looking back at most two thirds of a row); a word longer than a whole row is cut in the middle.
  2. Rows of the whole file as prefix sums: rowStart_[l] = first row of line l; a folded line adds 0 rows; rowStart_[lineCount] = all rows. Built in one O(N) pass by ensureRows, and only when it is used after the text, the folds or the width changed (invalidateRows just sets a flag).
  3. Row → line: binary search for the first line whose rows end after the row. Line → row: one array read. Both O(log n) / O(1).
  4. Mouse and keys: cellAt turns a click into (line, row of that line, column into the row). Up / Down move one screen row with posAtRow(row, x), keeping wantX_, the column into the row, until another key moves the cursor.
  5. Painting: each line draws its rows one under the other; every range (selection, search hit, squiggle, token) is cut per row by forRows.

Fails when: nothing throws. Above about 3 MB of text wrap switches itself off (wrapOn() is false) so typing stays fast. Continuation rows start at the left edge (no hanging indent). Cost: rebuild O(N); lookups O(log n); painting O(visible rows).

File: engine/DynArray.h. Fields: data (the block of slots), size (slots in use), capacity (slots allocated).

    IF newCap ≤ capacity THEN RETURN

    copy data[0 .. size-1] into the new block
    free the old block; data ← new block; capacity ← newCap

PUSH_BACK(x)
    IF size = capacity THEN
        RESERVE(capacity × 2, or 8 if capacity is 0)  // doubling
    data[size] ← x
    size ← size + 1

INSERT(i, x)
    IF i > size THEN fail "index out of range"
    IF size = capacity THEN RESERVE(capacity × 2, or 8)
    FOR k FROM size DOWN TO i+1:                   // shift right, start at the end
        data[k] ← data[k-1]
    data[i] ← x
    size ← size + 1

    gap ← last - first
    FOR k FROM last TO size-1:                     // shift the tail left over the gap
        data[k - gap] ← data[k]
    size ← size - gap

A3. Document (doubly linked list of lines): nodeAt, insertText, deleteRange

File: engine/Document.cpp. Each node is one line: { text: DynArray<char>, prev, next }. The list keeps head, tail, lineCount and a cache (the last node it visited and its line number).

NODE_AT(line)                                   // find the node of a line number
    IF line ≥ lineCount THEN fail "line number out of range"
    dHead  ← line                               // steps if we start at head
    dTail  ← lineCount-1 - line                 // steps if we start at tail
    dCache ← |line - cacheIdx|                  // steps if we start at the cache
    start from whichever of cache / head / tail is closest (cache wins a tie)
    WHILE index ≠ line:
        move one node forward (next) or backward (prev)
    cache ← this node; cacheIdx ← line
    RETURN the node

    check that at is a real position, otherwise fail before changing anything
    cur  ← NODE_AT(at.line)
    tail ← cur.text[at.col ..]                  // the part after the cursor
    cut cur.text at at.col
    FOR EACH character c IN text:
        IF c = '\r' THEN skip it
        ELSE IF c = '\n' THEN
            make a new node and link it right after cur   // fix prev/next (and tail)
            cur ← the new node
        ELSE append c to cur.text
    end ← (line of cur, length of cur.text)     // where the inserted text ends

A4. Hash table (separate chaining): hash, put, get, erase, grow

File: engine/HashTable.h. It is an array of buckets, and each bucket is a singly linked list (a chain) of (key, value) nodes. A key's bucket is hash(key) mod bucketCount. The table starts with 16 buckets and doubles before it gets more than 0.75 full.

HASH(s)                                         // FNV-1a, 64 bit
    h ← 1469598103934665603                     // the "offset basis"
    FOR EACH byte c IN s:
        h ← h XOR c
        h ← h × 1099511628211                   // the FNV prime (wraps around at 64 bits)
    RETURN h

FIND_NODE(key)
    b ← HASH(key) mod bucketCount
    FOR EACH node n IN the chain of bucket b:
        IF n.key = key THEN RETURN n
    RETURN nothing

PUT(key, value)                                 // insert, or overwrite an existing key
    n ← FIND_NODE(key)
    IF n exists THEN n.value ← value; RETURN false   // not new
    IF (size + 1) > 0.75 × bucketCount THEN GROW()
    b ← HASH(key) mod bucketCount
    new node (key, value) goes at the HEAD of chain b   // O(1)

A5. Trie (prefix tree): insert, find, remove, complete top-k

File: engine/Trie.cpp. Each node stands for one prefix. It has a list of edges (character → child) kept sorted by character, a flag isWord and a weight (how often the word was seen).

B1. KMP search: failure table and matching

File: engine/Search.cpp. f[i] is the length of the longest proper prefix of pattern[0..i] that is also a suffix of it. After a mismatch, KMP uses f to slide the pattern forward without ever moving back in the text.

BUILD_FAILURE_TABLE(p)                          // m = length of p
    f[0] ← 0; k ← 0                             // k = length of the current border
    FOR i FROM 1 TO m-1:
        WHILE k > 0 AND p[i] ≠ p[k]:
            k ← f[k-1]                          // fall back to a shorter border
        IF p[i] = p[k] THEN k ← k + 1
        f[i] ← k
    RETURN f

KMP_SEARCH(text, p)                             // the streaming matcher, one character at a time
    state ← 0                                   // how many pattern characters match right now
    FOR EACH position i, character c IN text:
        (if ignoring case: turn A-Z into a-z, in both text and pattern)
        WHILE state > 0 AND p[state] ≠ c:
            state ← f[state-1]                  // slide the pattern, keep i where it is
        IF p[state] = c THEN state ← state + 1
        IF state = m THEN
            report a match ending at i (it starts at i - m + 1)
            state ← f[m-1]                      // not 0, so overlapping matches are found too
    // a Document is searched line by line, feeding '\n' between lines,
    // so a pattern with a line break can match across lines.
    // "Whole word" then rejects a match that has a letter, digit or _ right next to it.

    IF query is empty THEN RETURN 0
    IF q > n THEN RETURN -1                    // cannot fit
    FOR EACH position j IN path:               // what a match at j is worth by itself

                   10 if it follows _ - . or a space
                    8 if it is a camelCase hump (lower case then UPPER)
                    0 otherwise

    // D[j]: best score with it matched at some k ≤ j (each skipped character costs 1)

B8. Code folding: fold ranges (counting sort), merged intervals, prefix sums, binary search

File: engine/Folding.cpp. A fold range (start, last) means: the header line start stays visible, and lines start+1 .. last are hidden when it is folded.

FOLD_RANGES_FROM_BRACKETS(pairs, lineCount)
    lastOf ← array of lineCount zeros          // one slot per line
    FOR EACH bracket pair (open, close):
        IF close.line ≥ open.line + 2 THEN     // at least one line to hide
            lastOf[open.line] ← the larger of itself and close.line - 1   // the closer stays visible
    FOR l FROM 0 TO lineCount-1:               // walking the slots in order = counting sort
        IF lastOf[l] > l THEN output range (l, lastOf[l])

REBUILD(folds sorted by start)                 // after fold / unfold
    hs, he, before ← empty arrays; hiddenTotal ← 0
    FOR EACH fold (start, last):
        a ← start + 1; b ← last                // the hidden lines
        IF a ≤ last he + 1 THEN                // overlaps or touches the previous interval
            extend it to b (if b is larger), add the extra lines to hiddenTotal
        ELSE
            before.ADD(hiddenTotal)            // lines hidden before this interval (prefix sum)
            hs.ADD(a); he.ADD(b); hiddenTotal ← hiddenTotal + (b - a + 1)

ROW_OF(line)                                   // which screen row shows this line
    k ← number of intervals with hs ≤ line     // binary search
    IF k = 0 THEN RETURN line
    IF line ≤ he[k-1] THEN line ← hs[k-1] - 1  // hidden: use the header above it
    hidden ← before[k-1] (+ size of interval k-1 if line is past it)
    RETURN line - hidden

LINE_AT(row)                                   // the opposite direction
    k ← number of intervals with hs - before ≤ row   // binary search
    IF k = 0 THEN RETURN row
    RETURN row + before[k-1] + size of interval k-1

B9. Outline: nesting of classes and functions with a stack

File: engine/Outline.cpp. For C / C++ the scanner looks at the header in front of each { pair from the bracket checker. For indentation languages (Python, scripts) it uses the indentation. Both use the same stack idea. The indentation version is shown here because it is the easiest to trace.

OUTLINE_BY_INDENT(lines)
    open ← empty stack of (indent, symbol index)   // symbols whose body is still going
    FOR EACH line l (skip blank lines and # comments):
        ind ← its indentation (a tab counts up to the next tab stop)
        WHILE open is not empty AND open.TOP.indent ≥ ind:

            open.PUSH(ind, its index)
    at the end, pop everything: endLine ← last non-blank line

File: gui/CodeView.cpp. With word wrap on, one line can take several screen rows. rowStart[l] = the first row of line l, which is a prefix sum of the rows each line needs.

Honest limitations (say these before they are found)

  • Snippets: one cursor marker ($0) only, at most 500 snippets, bodies up to 4,000 characters.
  • Compiler check: needs g++ / gcc on PATH and checks one file at a time with -fsyntax-only, so errors that depend on other files' include paths can be reported wrongly.
  • Terminal: runs commands through QProcess, not a pseudo-terminal, so full-screen programs do not display correctly.
  • Whole file in memory: opening a multi-gigabyte file is not supported.
  • ASCII case folding: case-insensitive search only folds A-Z.
  • Bracket checker is C-style: templates, Python triple-quote strings, and other languages' comments can cause false reports.
  • Out-of-memory (std::bad_alloc) is not caught anywhere.
  • Undo memory: a Delete keeps its text; a huge deletion is kept until trimmed (100 steps).
  • Remaining STL/Qt use: std::string, std::filesystem and Qt containers in the GUI; the structures the assignment is about are hand-written.
  • Linked-list random access is O(distance), mitigated by the cache.
  • F5 needs the compiler/interpreter installed and on PATH.
  • Outline is a heuristic: it reads the text, it does not parse C++. Unusual macros, oddly split headers or unbalanced brackets can hide or misread a symbol.
  • Folding of C-like code follows the brackets: while the brackets are unbalanced (half-typed code) some ranges vanish and folds on them are dropped; plain-text files do not fold.
  • Word wrap switches itself off above about 3 MB of text, and continuation rows start at the left edge (no hanging indent). Rebuilding the row table after an edit is O(N).
  • Terminal links need a file extension; Makefile:3 or paths with spaces are not recognised.
  • Ctrl+Shift+[ / ] could not be tested on every keyboard layout; Edit > Folding and the Command Palette always work.
  • GUI tests not re-run since the newest features: on this PC gui_tests stops at start-up (exit code -1073740286); only the engine tests are confirmed passing.
